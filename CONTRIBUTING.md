# Contributing

DistSSHBase is how a DistSSHKit family package names a host, reaches it over SSH, and prints help. Users add DistSSHKit. The manual for them is the README. This file is for people changing the repo.

Julia 1.13 or later, on macOS, Linux, or WSL2 Ubuntu. Not native Windows. How you install Julia is up to you. 1.13 is the floor in `.github/julia-slots.env`.

```bash
git clone https://github.com/yamanori99/DistSSHBase.jl.git
cd DistSSHBase.jl
julia --project=. -e 'using Pkg; Pkg.instantiate()'
julia --project=. -e 'using Pkg; Pkg.test()'
```

`Pkg.test()` is the unit tests. When you add or remove a file in `test/runtests.jl`, bump `_RUNTEST_N`. Before pushing Julia changes, format and run the checks that CI runs outside `Pkg.test()`.

Runic is installed once with `Pkg.Apps.add("Runic")`. It checks `.jl` files only. If a Runic update makes CI red, format again and push.

```bash
runic --inplace src test docs testenv
./.github/jetls-check.sh
./.github/aqua-check.sh
./testenv/docker-ssh/scripts/up.sh --e2e
julia --project=docs --color=yes docs/make.jl
```

## What CI requires

The `main` ruleset asks for these checks:

- `Pkg.test - 1.13 - ubuntu-latest`
- `JETLS - 1.13 - ubuntu-latest`
- `Aqua - 1.13 - ubuntu-latest`
- `Documenter - 1.13 - ubuntu-latest`
- `Gitleaks`
- `ubuntu-latest → ubuntu-24.04`
- `PR label`

`ubuntu-latest → ubuntu-24.04` is a Linux runner talking to SSH workers built from `ubuntu:24.04`. Markdown-only edits skip the heavy jobs. The skip list lives in `.github/actions/ci-heavy/action.yml`. A `Project.toml` version increase does not skip them.

Runic is not required. Once a month on `main` it opens `Runic monthly failed` if `--check` is red. Codecov uploads from `Pkg.test` on a push to `main` only, and the status is informational.

Sunday 04:00 JST, a manual run, or a version increase on `main` builds the worker image and runs the suite on `macos-15-intel` with Colima (`macos-15-intel → ubuntu-24.04`). That job is not required. On `main` it also publishes `distsshbase-linux-ssh-worker:latest`.

The Julia floor is the `1.13` line in `.github/julia-slots.env`. When it moves, rename the jobs and the ruleset in the same PR.

## Pull requests

Branch from `main`. One change per PR. Squash-merge, then the head is deleted.

Each PR needs one type label: `bug`, `enhancement`, `breaking`, or `chore`. The Type workflow fills it in from a closing issue, or from the branch prefix (`feat/`, `fix/`, otherwise `chore`). Path labels come from `.github/labeler.yml`, regenerated by `./.github/gen-labeler.sh`.

- `area:base` — `src/**`, `test/unit/**`, and package meta (`Project.toml`, `LICENSE`, `.gitignore`, `.gitattributes`, `.vscode/**`)
- `area:test` — the rest of `test/` and `testenv/**`
- `area:docs` — `docs/**`
- `area:project-docs` — README, NEWS, CONTRIBUTING, SECURITY
- `area:ci` — `.github/**`, `codecov.yml`, `.coderabbit.yaml`

CodeRabbit may comment. It is not a merge gate. The config is `.coderabbit.yaml` on the PR head.

## Release

`breaking` means incompatible behavior and can land without a version bump. A version cut is a higher `version` in `Project.toml`. There is no `cut` label. CI compares the file with the base.

On a breaking line, bump `x` in `0.x.y`. Otherwise bump `y`. Do not ship an empty cut, and do not automate the bump or `@JuliaRegistrator register`. Cut when `NEWS.md` under Unreleased has something General users of this package should get. Day-to-day users still add DistSSHKit.
